## 方法と限界

- 1〜60行では、固定ソースの同名 `FunctionDef` を `ast.get_source_segment` で取得し、台帳の開始・終了行とUTF-8 SHA-256を照合した（60/60一致）。hashは対応確認だけであり、判断根拠はテスト本文、helper、全parameter、owner、1-hop consumerと実在closestの照合である。
- JUnit時間は元のケース別setup/teardown込みの合計である。並列wall時間、削減後時間、flake率、保守時間は未計測。初回 full 実測を再実行していない。
- Rは現実的な故障を固有の境界で検出する維持判断、F/C/Dは対応を分離して追跡する候補、Uは必要な根拠を明示して未判定とする。ここでは1〜60行はすべてR、61〜139行はpendingのままである。
- code change時のCI経路は `.github/workflows/ci.yml` のTest shardからQualityであり、このdocs-only変更では対象テストは実行されない。
