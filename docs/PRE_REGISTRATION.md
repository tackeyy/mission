# 目的

README が現在**明示的に主張していない**クレームについて、**どの数値を満たせば主張してよいか**を、**データを収集する前に**確定させる。

# なぜ収集前に決めるのか

このプロジェクトの評価は**自己評価**である。結果を見てから基準や指標を選べる状態だと、都合の良い切り口を後から選べてしまい、第三者から見て信頼できない。

**事前登録（pre-registration）は、収集前に基準を commit しておき、レポートがその commit を参照する運用**である。これにより「結果を見てから基準を変える」ことが構造的に不可能になる。実装コストはほぼゼロで、自己評価の信頼性を担保する手段として最も費用対効果が高い。

**本 Issue が merge された後に取得したデータのみを、解禁判定に使う。**

# 現在主張していないクレーム（README より）

1. `mission` が平均的により高品質な成果物を作ること
2. goal ベースラインでは完遂できない作業を `mission` が完遂できること
3. 5% というテール率が他者のワークロードにも当てはまること
4. 現在のベンチマーク品質数値に意味があること

# 事前登録する解禁条件

## クレーム 1: 品質優位

**指標**: #587 で確定した構造化 findings 照合による F1（recall と precision の調和平均）

**必要条件（すべて満たすこと）**

| 条件 | 閾値 | 理由 |
|---|---|---|
| 計測器の感度検証を通過 | 劣化 arm との F1 差が 0.15 以上 | **これが最優先。** 差を検出できる計測器であることを先に証明する。通過しなければ他の条件は評価しない |
| `measurement_valid` | `true` | 飽和・弁別ゼロの run を根拠にしない（#563） |
| `marker_score_arm_sensitivity` | 1 以上 | 指標が arm の違いに感応していること（#585） |
| `statistical_confidence` | `adequate`（n>=3） | #565 |
| ペア数 | 30 以上（タスク 5 × repeats 3 × 2 arm） | |
| mission の F1 平均 − goal の F1 平均 | **+0.10 以上** | |
| mission が goal を下回ったタスク | **0 件** | 1 タスクでも逆転していれば「優位」とは言わない |

**満たした場合に許可される表現**: 「この cohort・この条件下で、mission は goal より高い F1 を示した」（条件を必ず併記する。一般化しない）

## クレーム 2: goal が完遂できない作業を完遂できる

**指標**: `completion == true` かつ validator 通過の有無

**必要条件**

| 条件 | 閾値 |
|---|---|
| 同一タスク・同一条件で goal が未達、mission が達成したペア | **3 件以上** |
| その逆（goal 達成・mission 未達）のペア | **0 件** |
| ペア数 | 30 以上 |

現在この事例は **0/120 vs 0/114 で 1 件も存在しない**。3 件は最低限の再現性の水準である。

## クレーム 3: テール率の一般化

**解禁しない。** 他者のワークロードの分布は本プロジェクトが観測できないため、どんなデータを集めても一般化はできない。README には「メンテナの環境での観測値である」と明記し続ける。

## クレーム 4: 現在のベンチマーク品質数値

**#587 の新採点方式へ置き換わった時点で、この項目は消滅する。** 旧 marker スコアは遡って有効にはならない。

# gate 精度（#593 / #594）の解禁条件

README に「ゲートの精度」を数値で載せるための条件。

| 条件 | 閾値 | 理由 |
|---|---|---|
| `missions_classifiable` | 20 以上 | digest を持つ multi-iteration mission がこの数に達するまで率を載せない |
| false positive 率 | 実測値をそのまま記載 | **閾値は設けない。** 不利な数値でも載せる |
| false negative | `status: "measured"` かつ `missions_with_verification` 20 以上 | verification 記録が貯まるまで「測定不能」と書き続ける |

**FP 率に閾値を設けないのは意図的である。** 「良い数字が出たら載せる」運用は publication bias そのものであり、透明性の主張と両立しない。**測れたら、値がどうであれ載せる。**

# コスト見積もり

セル数で示す（サブスクリプション実行のため従量課金は発生せず、消費するのはプランのレート制限）。

| 用途 | セル数 |
|---|---|
| 感度検証（劣化 arm 比較） | 5 タスク × 2 arm × 3 repeats = **30** |
| クレーム 1 の判定 run | 5 タスク × 2 arm × 3 repeats = **30** |
| clean control（precision） | 3 タスク × 2 arm × 3 repeats = **18** |
| **合計** | **約 78 セル** |

gate 精度（#593 / #594）は**追加の run を要さない**。日常利用で自然に蓄積する。

# 基準を変更する場合の規律

事前登録した基準を変更する場合は、**変更前のデータを見ていないこと**を条件とし、変更理由と変更日を本 Issue に記録する。**データを見た後の変更は、事前登録の無効化として扱い、その旨をレポートに明記する。**
